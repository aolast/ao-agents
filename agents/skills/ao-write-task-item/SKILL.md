## 术语约定

| 词汇 | 含义 | 回答的问题 |
| --- | --- | --- |
| 目标 | 希望达到的状态或效果。 | 希望变成什么样？ |
| 目的 | 追求目标或开展任务的理由。 | 为什么值得做？ |
| 成果 | 任务承诺取得、可以辨识和检查的结果。 | 这项工作具体要取得什么？ |
| 任务 | 为取得约定成果而设立，需要独立定义、推进和检查完成的工作单元。 | 要管理哪一项工作？ |
| 子任务 | 承担父任务部分成果的任务，仍适用任务的完整定义。 | 这项任务属于哪个父任务？ |
| 任务步骤 | 为取得任务成果而采取的具体行动，通常沿用所属任务的约定。 | 具体怎么做？ |

描述任务承诺时使用“预期成果”，描述执行所得时使用“实际成果”。成果可以是文档、判断、确认的安排、获得的条件或改变后的状态；“结果”作为一般用语，不另设管理概念。

目标表达期望的状态或效果，成果表达任务具体承诺取得什么，不按未来与过去区分。同一事项从不同角度可以既是目标，也是某个任务的预期成果；取得成果是否足以达成目标仍需检查，不能只依据任务步骤已执行来判断。

## 01 如何定义与拆解任务

### 定义任务

遵循我们定义的 CPQSRT 框架：

1. C-Context 当前情况是什么？有哪些事实、证据、假设？
2. P-Purpose 为什么做这项任务？它支撑什么目标，取得其成果为什么有价值？
3. Q-Quality 预期成果满足什么条件才算合格？用什么证据检查，达到什么状态才算任务完成？
4. S-Scope 本次承诺取得哪些成果，覆盖哪些对象或场景，做到哪里，明确不做什么，以及这些边界的原因？
5. R-Resource 可选，默认省略。有哪些关键的资源限制？比如影响任务推进的权限、外部支持、特殊工具、预算。
6. T-Time 可选，默认省略（除非有明确交代）。需要在什么时间点完成？比如强制的截止日期、协作时间要求等。

使用 SMART 框架检查一个任务描述是否合适：

1. S-Specific 对象、预期成果、边界是否明确？
2. M-Measurable 能否依据实际成果和证据检查完成，而不只是要求一个任务“做过了”？
3. A-Achievable 在当前已知条件下，该任务的承诺和要求是否合理、可行？
4. R-Relevant 该任务是否支撑相应目标，取得其成果为什么有价值？
5. T-Time-bound 该任务是否有明确的时间约定，如截止日期、检查点？该项在没有明确要求时可以跳过。

### 拆解任务

1. 区分任务与任务步骤。任务管理预期成果及其完成判据，任务步骤组织取得成果所需的动作、顺序和操作。任务步骤也可以有局部成果，不能仅凭“有成果”就将其拆成任务。
2. 将父任务的预期成果分解为值得独立管理的部分，为这些部分建立子任务；将任务展开为任务步骤，则是说明执行过程。子任务是任务的层级身份，不是另一种工作类型。一个任务可以同时包含子任务和任务步骤。
3. 拆出子任务前，应同时明确：它有可辨识的预期成果和完成判据；它确实需要独立规划、跟进或检查，保留为任务步骤会掩盖这些管理需要。
4. 分清目标关联、任务归属与依赖：
   - 目标关联：这项任务支撑什么目标。
   - 归属关系：这项任务属于哪个父任务；子任务承担父任务的一部分成果。
   - 依赖关系：推进任务或其中某个任务步骤之前，需要先取得什么成果或条件。写清依赖条件和受影响的部分，依赖不必发生在父子任务之间。

任务步骤全部执行或子任务全部完成，不自动代表该任务完成；仍需按该任务的完成判据检查整体成果。

## 02 处理模糊的目标和任务

任务并不总是一开始就清晰。随着推进获得新信息，逐渐补充和调整任务定义：

1. 不要求一次性定义所有任务。朝目标推进时收集信息，据此新增、删减或调整任务。
2. “还有未知”不等于不能开始，但也不等于可以无边界地行动。
   - 目标本身不清楚时，先确认希望达到的状态或效果。
   - 目标已知，但任务的预期成果或范围不清楚时，先补充任务定义。
   - 预期成果和范围已明确，但实现路径不清晰时，先取得决定下一步所需的信息。
   - 需要通过调研取得信息或形成判断，且值得独立管理时，可以创建调研任务，明确其预期成果和完成判据。
   - 当前任务已足以推进下一步，且进一步拆分没有明显管理价值时，停止细化。
3. 遇到不清楚或做不下去的情况，判断需要哪种调整：
   - 原有任务定义与实际情况不符或信息不足时，更新任务定义。
   - 任务的预期成果、范围和完成判据已明确，仅需调整实现方式时，更新任务步骤。
   - 发现需要取得、且值得独立规划、跟进和检查的成果时，创建新的任务；是否作为子任务，按成果归属判断。
4. 采用渐进的工作方式：推进当前工作 → 获取新信息 → 判断影响 → 做最小必要调整 → 继续推进或重新确认。对重要发现留下简短记录：
   - 发现：新事实是什么？原来的哪项假设不再成立？
   - 影响：影响哪些任务的预期成果、任务步骤、资源或时间限制？是否影响目标？
   - 处理：补充任务定义、调整任务步骤，还是创建新任务？
   - 重新检查：取得什么成果或信息，或遇到什么变化时重新判断？
