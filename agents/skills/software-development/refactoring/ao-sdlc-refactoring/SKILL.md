# 重构

本 skill 编排设计、实现、验证与审查，围绕行为保持的结构目标按需组合相关能力，复用已有结论。

先将“优化代码”转为具体结构目标及已有负担，例如重复规则经常不同步、职责交叉导致修改扩散。范围和是否值得此时处理使用 ao-sdlc-design；没有实际目标时先澄清，不默认扩大重写。

## 行为保持边界

明确需要保持的输入输出、错误、调用契约、顺序、数据与兼容行为。根据任务判断哪些性能或副作用约束也是契约的一部分。

若要求本身改变行为，将该部分明确标为行为变更，重新确认目标和验证；不要藏在“纯重构”描述中。发现既有 bug 时，评估是否阻碍重构并明确处理范围，不自动夹带修复。

## 执行方法

1. 使用 ao-sdlc-testing 判断现有证据能否保护相关行为。必要时先补特征测试（characterization tests）描述真实行为，但不把未经确认的 bug 升格为期望契约。
2. 选择能够逐步理解和验证的结构转换：移动职责、提取概念、消除重复知识、简化分支等。用 ao-sdlc-implementation 落实选定的结构转换。
3. 每个有意义的小步核对行为；避免把无关格式调整和语义变化混成难读的差异。工作中的小步不要求每步成为独立 commit，提交组织服从目标项目。
4. 对照原始结构目标和完整差异，检查是否只转移了复杂度、引入更多间接层或遗漏调用方。正式审查按 ao-sdlc-review 组织。

如果难以保持行为或验证成本超过预期，缩小范围或调整方案；当目标已达成时停止扩展，不追求全仓库统一风格。

## 交付

说明结构改善、所保持的行为范围、验证依据和明确例外。只有证据支持的范围才能声称行为未变；源码 diff 看起来等价不等于全部运行情况已证明。

## 边界示例

- 为减少重复而把两个不同权限域的规则合并，导致一方变更影响另一方：应保留规则独立性，不以代码行数减少证明重构成功。
- 重构时将空字符串当作缺失值处理，而基线接受它：这是可观察行为变化，需要明确需求，不能隐含纳入。
