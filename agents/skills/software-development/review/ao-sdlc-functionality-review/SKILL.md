# Functionality Review

从可观察行为判断实现是否满足需求。评审对象是代码及其运行证据；仅有设计稿时列明无法核实的实现部分。结构或命名问题若已造成错误行为，直接报告其具体后果，不因它也涉及代码质量而忽略。

## 评审方法

确认目标、验收条件、项目契约、基线与待审快照，未提交部分另行标明。阅读完整差异及必要调用方，建立“要求 → 入口与执行路径 → 可观察结果 → 验证证据”的对应关系。作者描述是意图，不能替代实际行为。

沿正常输入、转换、状态更新、副作用、返回与错误追踪执行；再根据实际影响选择关键边界、失败、取消和并发场景。已有保护需核对是否覆盖所有相关入口。复现或运行检查时使用适合当前环境的方法，记录实际命令与结果；不能运行时说明限制。

## Checklist

逐项记录已核实、有问题、待确认或不适用；未检查不能记为通过。检查深度由实际风险决定。

- [ ] **需求与接线**：目标行为是否实现，是否遗漏验收条件？新路径是否通过实际路由、注册、配置和消费者被使用？
- [ ] **正常行为**：输入、输出、顺序与副作用是否符合契约？调用方是否正确理解返回值和执行结果？
- [ ] **边界与表示**：空值、缺失、范围边界、集合顺序、数值精度、单位、时区和标识符语义是否正确？只检查本次相关条件。
- [ ] **状态与不变量**：状态转换、事务边界与部分更新是否完整？重复调用或中途失败后，关键不变量是否仍成立？
- [ ] **失败语义**：异常、错误码、fallback 和空结果是否被正确区分？失败是否会被转换成成功或触发错误的下游操作？
- [ ] **并发与副作用**：共享读写、乱序、重试和异步执行是否造成竞争、重复副作用或遗漏？超时、幂等与取消是否协调？
- [ ] **资源与退出**：连接、文件、锁和任务是否在提前返回、异常、取消或重启路径中正确释放或恢复？
- [ ] **安全与数据边界**：校验、授权、租户隔离和输出编码是否适用于实际操作？是否越权读写或泄漏敏感数据？
- [ ] **兼容与回归**：未要求改变的行为是否保持？调用方、API、配置、序列化、schema 和迁移中间状态是否符合兼容承诺？
- [ ] **运行约束**：所用 API 和版本是否在目标环境中可用？代表性负载下是否违反明确的延迟、容量或资源约束？性能收益是否有可比较证据？
- [ ] **验证有效性**：测试是否从契约推导结果，能否捕获关键风险？是否 mock 掉被验证的逻辑或复制实现计算预期值？修复有条件时是否在基线失败、修改后通过？
- [ ] **证据边界**：是否区分产品问题、环境失败与既有问题？模拟成功、静态阅读及旧版本结果能支持哪些结论，哪些场景仍未验证？

## 输出与复核

每个发现给出代码位置、输入或执行条件、预期与实际行为的差异、具体后果及证据，必要时提出最小修正方向。沿用项目严重度标准；区分阻塞问题、非阻塞建议和待确认项。无法建立因果链的疑点不写成已确认缺陷。

优先报告本次引入或加重的问题；既有问题只有确实阻碍当前目标时才作为阻塞理由。同一根因合并，不要求固定数量的 findings。列明已审版本、关键路径、实际执行的检查和未验证范围；没有实质问题时给出限定于已审范围的结论。

核对反证，修正后复核原问题及受影响路径；证据推翻意见时关闭。代码修改、运行有外部副作用的操作与发布意见，按用户已有授权执行。

## 判断边界

- 新实现捕获连接失败并返回空列表，调用方会删除结果中不存在的记录：沿失败到删除的链路报告，不能只写“异常处理不好”。
- 框架在所有到达路径上完成输入验证：该约束成立时，不要求每个内部函数重复校验。
- 测试 mock 了整个重试函数：成功返回不能证明重试边界和重复副作用正确。
- 函数没有采用 reviewer 偏好的抽象，但满足契约且没有具体行为问题：不据此生成 functionality finding。
